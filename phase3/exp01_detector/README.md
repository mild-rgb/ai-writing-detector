# phase 3 / exp01 — ModernBERT human-vs-AI detector

Training harness for the phase 3 corpus. **The reproducibility contract below is
the point of this directory**, not an appendix to it.

## Why the contract exists

Phase 2's exp01 (`../../phase2/exp01_modernbert/FINDINGS.md`) reproduced exactly
at two layers and not at all at the third:

| layer | verdict |
|---|---|
| data and splits | EXACT — `prep.py` regenerated byte-identical inputs |
| analysis | EXACT — every number recomputed from stored `probs` with no GPU; **six errors caught that way** |
| training | NOT REPRODUCIBLE, **and no environment was captured** |

The environment gap was named there as "the biggest gap, and the cheapest to
have closed — a dozen lines writing `pip freeze` and `nvidia-smi` per record."
This directory closes it, and `code/contract.py` makes the closure testable
rather than aspirational.

## What every training record carries

Self-contained, in `results/results.jsonl`, one JSON line per run. Records are
self-contained deliberately: a sidecar file is exactly what goes missing.

| field | contents |
|---|---|
| `env` | full `pip freeze`, torch / transformers / CUDA / cuDNN, GPU model, driver version, TF32 and cuDNN flags, a hash of the code files themselves |
| `seeds` | `weight_init` and `data_order`, **separately** — they are different seeds and are never conflated |
| `hp` | every hyperparameter, including any `lr` swept down on divergence |
| `data` | sha256 of `docs.jsonl` and `splits.json`, plus this cell's own train/val/test id hashes |
| `code_path` | gradient checkpointing on/off, attention implementation, `reference_compile`, `classifier_pooling`, precision |
| `probs` | **per-document probabilities, test and val. Hard rule.** |
| `per_generator` | every metric broken out by generator. Never a pooled rate. |
| `tokenisation` | token-length distribution and truncation counts per split |

`python code/contract.py results/results.jsonl` checks all of it and exits
nonzero on a violation. Run it before reporting anything.

## What this does NOT promise

Not bitwise determinism, and unavoidable floating-point nondeterminism is not
treated as a failure. Phase 2 *measured* the same seed with gradient
checkpointing toggled moving accuracy **0.9347 → 0.9034**, purely from
floating-point non-associativity; a different GPU or CUDA build does the same.
Its seed spread (0.9034–0.9460, range 0.043) already exceeded most effects of
interest.

So: pin and log everything specifiable, then expect wobble. **The standard is
that conclusions reproduce** — ordinal and directional findings across seeds,
reported as mean ± SD — **not that a single number reappears.** `aggregate.py`
reports mean ± SD and refuses to present a single run as a result.

Phase 2's exp02 requirement was 5–10 seeds; three cannot support a variance
claim. The default here is 5 and `aggregate.py` says so when a group has fewer.

## Recipe

Pre-registered, not tuned against test. Deviations land in the record's `hp`.

```
ModernBERT-large   bf16 (never fp16)
attn_implementation = "sdpa"       flash_attention_2 has a known NaN bug
reference_compile   = False        the compile path changes numerics run to run
lr 3e-5 (swept down only on divergence)   weight_decay 8e-6   2-3 epochs
classifier_pooling: cls vs mean swept — our documents are long
max_length 2048 (corpus max ~1800 tok; chosen so nothing truncates)
```

Validation is the corpus **dev** split, so there is no carve seed to record.
Test is touched once per run, for scoring. Best epoch is chosen on dev AUC. A
dev-chosen decision threshold is reported *alongside* the pre-declared 0.5,
never instead of it, and never chosen on test.

## Cells

Two families, each in `raw` and `norm`:

- **`binary|{raw,norm}`** — all seven generators seen in training. Scored per
  generator on the test split.
- **`logo|<generator>|{raw,norm}`** — leave-one-generator-out, **the real
  generalization test**. The held-out generator's questions are removed *whole*
  from train and val — the AI answer and its paired human answer both — so the
  test set is naturally balanced and nothing about those questions was seen.

`norm` (whitespace collapsed) is the headline; `raw` exists only to measure how
much of a result is whitespace. Phase 2 found removing the artifact *improved*
every class and collapsed seed variance 15×. Each record also stores
`newline_baseline_auc`, the newline count alone as a detector on that exact test
set — 0.500 by construction under `norm`, which is the proof that a `norm`
result is not whitespace.

## Checkpointing and warm restarts

Checkpoints are **full state** — model, optimizer, scheduler and RNG — written
every `ckpt_steps` (default 100, ~1/5 epoch). Not weights-only: a run killed
mid-way resumes where it stopped rather than redoing the epoch.

The checkpoint directory is named by the run's `run_key_hash`, so a warm start
can only ever resume a run of byte-identical identity — same cell, both seeds,
model, pooling, gradient checkpointing, every hyperparameter, the train/test id
hashes. A leftover checkpoint from a different recipe cannot be picked up.

`save_total_limit` (default 2) caps VM disk; the best checkpoint is protected
from deletion. A run's checkpoints are removed once it finishes and its record is
written, unless `--keep-checkpoints` — the record is the artifact, and the
checkpoint was only insurance against a mid-run death.

Cadence lives in `hp` and therefore in the run key, because it sets how often dev
is scored and so which step is selected as best. It is part of the recipe.
`save_total_limit` and mirroring are **not** in the key: they change disk, never
a number. `--ckpt-strategy epoch` reproduces phase 2's cadence if a direct
comparison is ever wanted.

Every record states whether that run was warm-started (`resumed_from_checkpoint`).
A resumed run restores RNG state but still need not match an uninterrupted run
bit for bit, and a reader has to be able to tell the two apart.

Checkpoints protect against a kernel death. They do **not** survive a VM
recycle unless mirrored — `MIRROR_CKPT=1 bash code/run_sweep.sh ...`, opt-in
because a ModernBERT-large full checkpoint is several GB.

## Reserved: external evaluation on wild AI text

Planned, not built. A generalization check on in-the-wild AI text (Wattpad
stories flagged by Pangram), hand spot-checked, as a realism test that LOGO
cannot give — LOGO holds out a *generator*, but every document in this corpus was
produced to the same prompt against the same questions.

**Those labels are never training labels.** The hook is evaluation-only.

What is in place for it: `--final-model-dir DIR` persists each finished model
keyed by its run hash, with a `run_record_meta.json` carrying the run key, seeds,
hyperparameters, code path and data hashes, so a model can be traced back to
exactly the run that produced it. Without it the models are deleted with their
checkpoints and no later evaluation is possible.

One thing to get right when it is built: external text must go through the same
`norm_ws` as training (`prep.py`), or the comparison is against a different
preprocessing regime and measures that instead.

## The marker floor

`newline_baseline_auc` proves a `norm` result is not *whitespace*. It does not
prove it is not *Reddit*: the human class is real ELI5 answers and still carries
`Edit:` lines, `/r/` references, markdown bullets, first-person voice and mild
profanity after every run of whitespace has been collapsed.

`code/marker_baseline.py` is the wider control — a logistic regression on nothing
but the presence/absence of `phase3/scripts/markers.py`'s marker set, the
project's own mechanical regexes, scored on the same splits and reported per
generator. Presence, not counts, so length cannot leak in.

On the finished corpus under `norm` it reaches **AUC 0.687** overall
(0.611 deepseek → 0.807 nemotron). That is the floor a trained detector has to
clear. Landing near it would mean the expensive model is doing what forty
regexes do, and the honest headline would be the floor.

## The bag-of-words floor — read this before quoting any transformer number

The marker floor (0.687) turned out to be far too easy a bar. The binding
control is bag-of-words:

```
                                          AUC      balanced acc
  newline count alone (norm)             0.500        —          by construction
  ~40 mechanical markers                 0.687       0.631
  bag-of-words, words + punctuation      0.9997      0.9897
  bag-of-words, PUNCTUATION DELETED      0.9993      0.9845
  ModernBERT-large                       ~1.0000     ~1.0000
```

A logistic regression on binary word-presence — no ordering, no syntax, no
embeddings, no GPU — reaches **AUC 0.999**. So a transformer at ~1.000 is not
evidence that it understands prose. It is evidence that **the two classes are
nearly separable in plain word space**, which costs seconds to establish.

Report the transformer above this floor, never against 0.5.

### What it is not

Interrogated rather than assumed, because a perfect score is a claim:

- **Not one leaked token.** The best single feature on test reaches balanced
  accuracy 0.814 (`(` and `)`, present in 76.6% of human documents and 13.8% of
  AI ones). Nothing individually separates the classes.
- **Not punctuation.** Delete every punctuation mark and bag-of-words still
  scores AUC 0.9993. Ordinary vocabulary carries it.
- **Not the generator's blacklist.** The floor prompt forbids *delve, crucial,
  vital, robust, leverage, tapestry…* — so an obvious worry is that the detector
  learns "avoided the banned list ⇒ AI". It does not: banned terms appear in
  8.6% of human documents and 1.7% of AI ones, and the rule "no banned term ⇒
  AI" reaches balanced accuracy **0.534**. The ban is obeyed and is nearly
  irrelevant to the task.

The separation is real, distributed across ordinary word choice, and not an
artifact of the corpus build. That is a finding about this corpus, and it makes
the out-of-domain test the load-bearing one — everything here shares a single
prompt, a single length calibration, and a single source of human text.

## Reporting rule

**Per generator, always. Never a pooled rate.** Judged detection on this corpus
ranges from 6.7% (GPT Luna) to 80% (Nemotron) — a 73-point spread. A pooled
number is an average over things that are not alike, and it hides which model is
the failure. The spread is the honest headline.

## Running it

```bash
python prep.py --require-complete          # after the corpus is finished
python code/smoke_test.py --offline        # laptop pre-flight

# on Colab
bash code/setup_colab.sh /content/exp01
python code/smoke_test.py                  # one real short run, contract-checked
bash code/run_sweep.sh /content/exp01 --init-seeds 0,1,2,3,4 --pooling cls \
     --final-model-dir /content/drive/MyDrive/exp01_phase3/models

python code/contract.py results/results.jsonl
python code/aggregate.py results/results.jsonl
```

`run_sweep.sh` detaches the sweep from the kernel and mirrors results off the
VM, because Colab drops kernels and scratch does not survive a VM recycle.
Restarting resumes: `train_cell.py` skips any run whose `run_key_hash` is
already recorded, and that hash covers the cell, both seeds, the model, pooling,
gradient checkpointing, every hyperparameter, and the train/test id hashes — so
a resume can never silently confuse two different recipes.

## transformers 5.x gotchas, found by the smoke test

Both of these failed the first real run and are now guarded:

- **`classifier_pooling` and `reference_compile` are config fields, not
  `from_pretrained` kwargs.** transformers 5.15.1 forwards unrecognised kwargs
  into the model `__init__` and raises. They are set on an `AutoConfig` and then
  **read back off the loaded model**, so the record states what the model
  actually has rather than what was asked for. Asserted, not assumed — a silently
  substituted `attn_implementation` would mean training under the
  flash-attention NaN bug while the record claimed `sdpa`.
- **`save_safetensors` no longer exists** on `TrainingArguments`. Rather than
  chase these one per run, the argument dict is checked against the installed
  dataclass fields up front and unknown keys are named in the error. It refuses
  to run rather than dropping them — silently dropping `bf16`, a seed, or the
  checkpoint cadence would change the recipe with nothing in the record to show
  it.

## A note on the corpus

`answers.jsonl` carries a `split` field stamped at generation time and it is
**stale for some rows** — the question-level split was revised afterwards.
`questions.jsonl` is authoritative. `prep.py` takes the question's split and
records the disagreement count in `dataset_card.json`. Reading the answer's
split instead would move held-out documents into training.
